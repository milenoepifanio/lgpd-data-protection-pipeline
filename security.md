# Política de Segurança

## Objetivo

Este projeto tem finalidade educacional e demonstra práticas de classificação, proteção e validação de dados conforme conceitos da LGPD.

## Como relatar uma vulnerabilidade

Não publique vulnerabilidades, dados pessoais, credenciais ou informações sensíveis em issues, pull requests ou discussões públicas.

Para relatar um problema de segurança:

1. Utilize um canal privado do repositório, como um GitHub Security Advisory, quando disponível.
2. Descreva o problema, os passos para reproduzi-lo, o impacto observado e uma possível correção.
3. Remova ou anonimize qualquer dado pessoal incluído no relato.

Caso o repositório não ofereça um canal privado, entre em contato com os mantenedores antes de divulgar o problema publicamente.

## Escopo

Relatos relacionados a exposição de dados, credenciais, permissões inadequadas, bypass de proteção ou comportamento inseguro são considerados relevantes.

Arquivos de exemplo e dados sintéticos não devem conter informações pessoais reais. Não inclua segredos em commits, notebooks, arquivos `.env` ou mensagens de erro.

## Tratamento dos relatos

Os mantenedores analisarão o relato, confirmarão sua recepção quando possível e trabalharão em uma correção ou mitigação. A divulgação pública deve ocorrer somente após a correção ou após uma decisão conjunta com os envolvidos.

Este documento não substitui uma avaliação jurídica, de privacidade ou de segurança para ambientes de produção.
