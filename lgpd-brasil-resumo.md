# Lei Geral de Proteção de Dados — LGPD

## Sobre

A **Lei Geral de Proteção de Dados Pessoais (LGPD) — Lei nº 13.709/2018** estabelece regras para o tratamento de dados pessoais por pessoas naturais e organizações públicas ou privadas.

Seu principal objetivo é proteger os direitos fundamentais de:

- liberdade;
- privacidade;
- intimidade;
- desenvolvimento da personalidade da pessoa natural.

A LGPD não trata apenas de dados armazenados digitalmente. Suas regras abrangem operações de tratamento de dados pessoais independentemente do meio utilizado.

---

# 1. Conceitos Fundamentais

## 1.1 Dado Pessoal

É qualquer informação relacionada a uma pessoa natural **identificada ou identificável**.

Exemplos:

- nome;
- CPF;
- e-mail;
- telefone;
- endereço;
- matrícula;
- identificadores digitais;
- informações que, combinadas, permitam identificar uma pessoa.

---

## 1.2 Dado Pessoal Sensível

É uma categoria de dado pessoal que exige maior proteção devido ao potencial de causar discriminação ou impactos relevantes ao titular.

São dados relacionados a:

- origem racial ou étnica;
- convicção religiosa;
- opinião política;
- filiação sindical;
- organização religiosa, filosófica ou política;
- saúde;
- vida sexual;
- dados genéticos;
- dados biométricos vinculados a uma pessoa.

---

## 1.3 Dado Anonimizado

É o dado que não permite identificar seu titular considerando os meios técnicos razoáveis e disponíveis.

Em regra, dados efetivamente anonimizados não são considerados dados pessoais pela LGPD.

Entretanto, se a anonimização puder ser revertida utilizando meios razoáveis, esses dados podem voltar a ser considerados dados pessoais.

---

## 1.4 Titular

É a **pessoa natural a quem os dados pessoais pertencem**.

Exemplo:

Uma empresa possui uma base de clientes.

O cliente é o **titular dos dados** armazenados nessa base.

---

## 1.5 Tratamento de Dados

Tratamento é praticamente qualquer operação realizada com dados pessoais.

Inclui atividades como:

- coleta;
- recepção;
- classificação;
- utilização;
- acesso;
- reprodução;
- processamento;
- armazenamento;
- arquivamento;
- alteração;
- compartilhamento;
- transmissão;
- transferência;
- eliminação.

Portanto, a LGPD não se aplica apenas à coleta ou ao armazenamento. Ela acompanha praticamente **todo o ciclo de vida do dado**.

---

# 2. Agentes Envolvidos

## 2.1 Controlador

É quem toma as **decisões referentes ao tratamento dos dados pessoais**.

Exemplo:

Uma empresa decide quais dados de seus clientes serão coletados e para quais finalidades.

Nesse contexto, a empresa atua como **controladora**.

---

## 2.2 Operador

É quem realiza o tratamento dos dados pessoais **em nome do controlador**.

O operador deve realizar o tratamento seguindo as instruções fornecidas pelo controlador.

---

## 2.3 Encarregado

É a pessoa indicada para atuar como canal de comunicação entre:

- controlador;
- titulares dos dados;
- Agência Nacional de Proteção de Dados (ANPD).

Entre suas atividades estão:

- receber reclamações e comunicações dos titulares;
- prestar esclarecimentos;
- receber comunicações da autoridade;
- orientar funcionários e contratados sobre práticas de proteção de dados.

---

## 2.4 Agentes de Tratamento

A LGPD utiliza o termo **agentes de tratamento** para representar:

- controlador;
- operador.

---

# 3. Princípios da LGPD

As atividades de tratamento devem observar a **boa-fé** e dez princípios fundamentais.

## 3.1 Finalidade

Os dados devem ser tratados para propósitos:

- legítimos;
- específicos;
- explícitos;
- informados ao titular.

O dado não deve posteriormente ser utilizado de maneira incompatível com a finalidade original.

---

## 3.2 Adequação

O tratamento deve ser compatível com a finalidade informada ao titular.

---

## 3.3 Necessidade

Devem ser tratados somente os dados **necessários para atingir a finalidade**.

Esse princípio está diretamente relacionado à ideia de **minimização de dados**.

---

## 3.4 Livre Acesso

O titular deve poder consultar gratuitamente informações sobre:

- como seus dados são tratados;
- por quanto tempo;
- quais dados estão sendo tratados.

---

## 3.5 Qualidade dos Dados

Os dados devem ser:

- corretos;
- claros;
- relevantes;
- atualizados quando necessário.

---

## 3.6 Transparência

O titular deve receber informações claras, precisas e acessíveis sobre o tratamento de seus dados.

---

## 3.7 Segurança

Devem existir medidas técnicas e administrativas para proteger os dados contra:

- acessos não autorizados;
- perda;
- destruição;
- alteração;
- comunicação ou exposição indevida.

---

## 3.8 Prevenção

Devem ser adotadas medidas para prevenir danos decorrentes do tratamento de dados pessoais.

---

## 3.9 Não Discriminação

Dados pessoais não podem ser tratados para fins discriminatórios ilícitos ou abusivos.

---

## 3.10 Responsabilização e Prestação de Contas

Os agentes devem ser capazes de **demonstrar que adotaram medidas eficazes para cumprir a LGPD**.

---

# 4. Bases Legais para Tratamento

Um ponto importante da LGPD é que:

> **Consentimento não é a única forma de permitir o tratamento de dados pessoais.**

A lei estabelece diferentes hipóteses que podem fundamentar o tratamento.

Entre as principais estão:

1. consentimento do titular;
2. cumprimento de obrigação legal ou regulatória;
3. execução de políticas públicas;
4. realização de estudos por órgão de pesquisa;
5. execução de contrato ou procedimentos relacionados ao contrato;
6. exercício regular de direitos em processos;
7. proteção da vida ou da integridade física;
8. tutela da saúde;
9. legítimo interesse;
10. proteção do crédito.

A organização deve identificar qual hipótese legal justifica cada operação de tratamento.

---

# 5. Consentimento

Quando o tratamento depender de consentimento, ele deve representar uma manifestação:

- livre;
- informada;
- inequívoca;
- relacionada a uma finalidade determinada.

Autorizações genéricas para tratamento de dados não são válidas.

Além disso:

- o controlador deve conseguir demonstrar que obteve o consentimento adequadamente;
- o consentimento pode ser revogado;
- a revogação deve possuir procedimento gratuito e facilitado;
- mudanças relevantes na finalidade devem ser informadas ao titular.

---

# 6. Legítimo Interesse

O legítimo interesse pode ser utilizado como fundamento para tratamento em determinadas situações concretas.

Quando essa base é utilizada:

- deve existir uma finalidade legítima;
- devem ser consideradas as expectativas do titular;
- os direitos e liberdades fundamentais do titular devem ser respeitados;
- somente os dados estritamente necessários devem ser tratados;
- devem existir medidas de transparência.

A ANPD também pode solicitar um **Relatório de Impacto à Proteção de Dados Pessoais** relacionado ao tratamento.

---

# 7. Dados Pessoais Sensíveis

Dados sensíveis possuem regras específicas de tratamento.

O tratamento pode ocorrer, por exemplo:

- mediante consentimento específico e destacado;
- para cumprimento de obrigação legal;
- para execução de políticas públicas;
- para pesquisas;
- para exercício regular de direitos;
- para proteção da vida;
- para tutela da saúde;
- para prevenção à fraude e segurança do titular.

Por apresentarem maior risco aos direitos dos titulares, esses dados exigem atenção especial.

---

# 8. Dados de Crianças e Adolescentes

O tratamento de dados pessoais de crianças e adolescentes deve ocorrer considerando seu **melhor interesse**.

Para crianças, a lei estabelece, entre outras regras:

- consentimento específico e destacado de pelo menos um dos pais ou responsável legal;
- transparência sobre os dados coletados e sua utilização;
- coleta somente dos dados necessários;
- esforços razoáveis para verificar o consentimento do responsável;
- apresentação das informações de maneira simples, clara e acessível.

---

# 9. Direitos do Titular

O titular possui diversos direitos sobre seus dados pessoais.

Entre os principais:

- confirmação da existência de tratamento;
- acesso aos dados;
- correção de dados incompletos, inexatos ou desatualizados;
- anonimização de dados;
- bloqueio de dados;
- eliminação de dados tratados irregularmente;
- portabilidade;
- informação sobre compartilhamento;
- informação sobre a possibilidade de negar consentimento;
- revogação do consentimento.

O exercício desses direitos deve ocorrer mediante requisição do titular ou de seu representante legal.

---

# 10. Decisões Automatizadas

O titular pode solicitar a revisão de decisões tomadas **unicamente com base em tratamento automatizado de dados pessoais** quando essas decisões afetarem seus interesses.

Isso inclui decisões relacionadas à definição de perfis:

- pessoais;
- profissionais;
- de consumo;
- de crédito;
- relacionados a aspectos da personalidade.

Quando solicitado, o controlador deve fornecer informações claras sobre os critérios e procedimentos utilizados, respeitados os segredos comercial e industrial.

---

# 11. Ciclo de Vida dos Dados

Uma forma prática de interpretar a LGPD é pensar no ciclo de vida do dado:

```text
Coleta
  ↓
Armazenamento
  ↓
Processamento
  ↓
Utilização
  ↓
Compartilhamento
  ↓
Retenção
  ↓
Eliminação ou Anonimização
```

Durante todo esse processo devem ser observados:

- finalidade;
- necessidade;
- segurança;
- transparência;
- direitos do titular.

O tratamento deve terminar quando, por exemplo:

- sua finalidade for alcançada;
- os dados deixarem de ser necessários;
- terminar o período de tratamento;
- houver revogação do consentimento, quando aplicável;
- houver determinação da autoridade competente.

---

# 12. Segurança dos Dados

Os agentes de tratamento devem implementar medidas **técnicas e administrativas** capazes de proteger os dados pessoais.

Essas medidas devem reduzir riscos relacionados a:

- acesso não autorizado;
- destruição;
- perda;
- alteração;
- comunicação indevida;
- tratamento inadequado ou ilícito.

A proteção deve ser considerada desde a concepção do produto ou serviço até sua execução.

---

# 13. Incidentes de Segurança

Quando ocorrer um incidente de segurança que possa gerar **risco ou dano relevante aos titulares**, o controlador deve realizar a comunicação prevista pela LGPD à autoridade competente e aos titulares.

Um incidente pode envolver situações como:

- vazamento de dados;
- acesso indevido;
- perda de informações;
- exposição de bases;
- comprometimento de informações pessoais.

Um processo de resposta pode ser representado como:

```text
Detectar
   ↓
Avaliar
   ↓
Responder
   ↓
Comunicar
   ↓
Corrigir
```

---

# 14. Boas Práticas e Governança

Controladores e operadores podem estabelecer programas de governança e boas práticas relacionados à proteção de dados.

Esses programas podem envolver:

- políticas internas;
- procedimentos;
- padrões técnicos;
- controles de segurança;
- treinamento de funcionários;
- gestão de riscos;
- mecanismos de supervisão;
- tratamento de solicitações dos titulares;
- resposta a incidentes.

A LGPD, portanto, também possui relação direta com **governança de dados e segurança da informação**.

---

# 15. Registro das Operações de Tratamento

Controladores e operadores devem manter registros das operações de tratamento de dados pessoais que realizam, especialmente quando o tratamento estiver baseado em legítimo interesse.

Na prática, é importante conseguir responder perguntas como:

- Quais dados são tratados?
- De onde eles vêm?
- Por que são utilizados?
- Qual é a base legal?
- Onde são armazenados?
- Quem possui acesso?
- Com quem são compartilhados?
- Por quanto tempo são mantidos?

---

# 16. Relatório de Impacto à Proteção de Dados

O **Relatório de Impacto à Proteção de Dados Pessoais** documenta processos de tratamento que podem gerar riscos às liberdades civis e aos direitos fundamentais.

O relatório pode incluir:

- tipos de dados coletados;
- metodologia de coleta;
- medidas de segurança;
- riscos identificados;
- salvaguardas;
- mecanismos utilizados para mitigação dos riscos.

A autoridade competente pode determinar sua elaboração em determinadas situações.

---

# 17. Transferência Internacional de Dados

A LGPD estabelece regras para transferências de dados pessoais para outros países ou organismos internacionais.

A transferência pode ocorrer nas hipóteses previstas pela lei, como quando:

- existe nível adequado de proteção;
- existem garantias apropriadas;
- são utilizadas cláusulas contratuais;
- existem normas corporativas globais;
- há consentimento específico do titular;
- outras hipóteses legais aplicáveis são atendidas.

Portanto, armazenar ou processar dados em infraestrutura localizada fora do Brasil também deve ser considerado na governança dos dados.

---

# 18. Responsabilidade

Controladores e operadores podem responder por danos causados durante atividades de tratamento realizadas em violação à legislação de proteção de dados.

Os danos podem ser:

- patrimoniais;
- morais;
- individuais;
- coletivos.

Por isso, conformidade com a LGPD envolve não apenas possuir políticas, mas também conseguir demonstrar que controles e medidas adequadas são efetivamente aplicados.

---

# 19. Sanções Administrativas

Infrações à LGPD podem resultar em sanções administrativas aplicadas pela autoridade competente.

Entre as sanções previstas estão:

- advertência;
- multa;
- publicização da infração;
- bloqueio dos dados pessoais relacionados à infração;
- eliminação dos dados relacionados à infração;
- suspensão de determinadas atividades de tratamento;
- proibição parcial ou total de atividades relacionadas ao tratamento de dados.

A aplicação das sanções considera diferentes fatores previstos na própria legislação.

---

# 20. LGPD Aplicada à Engenharia de Dados

Para Engenharia de Dados, a LGPD possui impacto direto no desenho e operação de:

- pipelines;
- Data Lakes;
- Data Warehouses;
- bancos de dados;
- APIs;
- sistemas de integração;
- plataformas analíticas.

---

## 20.1 Coleta

Coletar apenas os dados necessários para determinada finalidade.

Evitar:

```text
"Vamos ingerir tudo porque talvez seja útil no futuro."
```

Preferir:

```text
Fonte
  ↓
Identificação da finalidade
  ↓
Seleção dos dados necessários
  ↓
Ingestão
```

Isso está diretamente relacionado ao princípio da **necessidade**.

---

## 20.2 Controle de Acesso

Nem todos os usuários ou sistemas precisam acessar todos os dados.

Aplicar conceitos como:

- princípio do menor privilégio;
- RBAC;
- segregação de ambientes;
- controle de acesso a tabelas e schemas;
- gestão adequada de permissões.

Exemplo:

```text
Data Lake
│
├── Dados Públicos
│     └── acesso amplo
│
├── Dados Internos
│     └── acesso restrito
│
└── Dados Sensíveis
      └── acesso altamente restrito
```

---

## 20.3 Dados Sensíveis

É importante identificar e classificar campos pessoais e sensíveis dentro das bases.

Exemplo:

```text
customer_id
name
email
cpf             ← dado pessoal
health_status   ← dado pessoal sensível
purchase_value
```

Essa classificação permite aplicar controles de segurança diferentes dependendo da criticidade da informação.

---

## 20.4 Anonimização e Pseudonimização

Sempre que possível, deve-se reduzir a exposição direta de informações identificáveis.

Exemplo:

```text
CPF
 ↓
Pseudonimização
 ↓
customer_id
```

Isso permite que pipelines analíticos utilizem identificadores internos em vez de informações diretamente identificáveis.

---

## 20.5 Logs

Logs também podem conter dados pessoais.

Deve-se evitar registrar desnecessariamente informações como:

```text
CPF
e-mail
telefone
dados pessoais sensíveis
```

Além disso, informações relacionadas a autenticação e segurança devem receber proteção adequada.

---

## 20.6 Retenção

Dados não devem necessariamente permanecer armazenados indefinidamente.

Uma arquitetura deve considerar o ciclo de retenção:

```text
Coleta
   ↓
Uso
   ↓
Período de Retenção
   ↓
Eliminação / Anonimização
```

A política de retenção deve considerar a finalidade do tratamento e as hipóteses legais que permitam eventual conservação dos dados.

---

## 20.7 Segurança

Pipelines devem considerar controles como:

- criptografia em trânsito;
- criptografia em repouso;
- gerenciamento seguro de credenciais;
- controle de acesso;
- segregação de ambientes;
- monitoramento;
- auditoria;
- rastreabilidade.

---

## 20.8 Rastreabilidade

É importante conseguir identificar como os dados percorrem a arquitetura.

Exemplo:

```text
API
 ↓
Raw / Bronze
 ↓
Staging / Silver
 ↓
Curated / Gold
 ↓
Data Warehouse
 ↓
Power BI
```

Para dados pessoais, é importante conhecer:

- origem;
- transformações;
- armazenamento;
- consumidores;
- compartilhamentos;
- período de retenção.

Esse conhecimento facilita governança, auditoria e atendimento aos direitos dos titulares.

---

# 21. Resumo

A LGPD pode ser resumida em alguns conceitos fundamentais:

**Dados pessoais**  
→ Informações relacionadas a pessoas identificadas ou identificáveis.

**Dados sensíveis**  
→ Informações que recebem proteção específica devido ao maior risco ao titular.

**Finalidade**  
→ Saber por que os dados estão sendo tratados.

**Necessidade**  
→ Utilizar somente os dados necessários.

**Base legal**  
→ O tratamento precisa estar enquadrado em uma das hipóteses previstas pela legislação.

**Transparência**  
→ O titular deve receber informações claras sobre como seus dados são utilizados.

**Segurança**  
→ Os dados precisam ser protegidos durante todo o ciclo de vida.

**Direitos do titular**  
→ Pessoas possuem direitos relacionados ao acesso, correção, eliminação, portabilidade e outras operações sobre seus dados.

**Responsabilização**  
→ Os agentes precisam conseguir demonstrar a adoção de medidas adequadas para proteção dos dados.

---

# 22. Visão Geral para Engenharia de Dados

Em uma arquitetura de dados, a LGPD pode ser pensada de forma simplificada como:

```text
                  LGPD
                    │
        ┌───────────┼───────────┐
        │           │           │
    Finalidade   Segurança   Governança
        │           │           │
        ↓           ↓           ↓
   Necessidade    Acesso     Rastreabilidade
        │           │           │
        ↓           ↓           ↓
 Minimização   Criptografia   Retenção
        │           │           │
        └───────────┼───────────┘
                    ↓
             Proteção dos Dados
```

Para Engenharia de Dados, isso significa incorporar conceitos de **privacidade, segurança, minimização, rastreabilidade e governança ao longo de todo o ciclo de vida dos dados**, desde a ingestão até sua utilização e eventual eliminação.
